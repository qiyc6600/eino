# 现场演示脚本

> 本文档提供 6 个逐步演示场景，覆盖所有模块的核心功能，适合现场验收演示。

---

## 前置准备

```bash
cd agent-eino-demo
go run ./cmd/server
```

浏览器打开 `http://localhost:8080`。

---

## 场景 1：登录与会话校验

**演示目标**：验证登录流程和未认证请求拒绝。

### 步骤

1. **不登录直接发消息**
   - 打开页面，不输入用户名密码
   - 直接在聊天框输入 `你好`
   - 预期：请求被拒绝，返回 401

2. **visitor 登录**
   - 用户名：`visitor`，密码：`visitor123`
   - 点击登录
   - 预期：左侧显示用户信息 `visitor`，角色 `visitor`
   - 预期：可用工具列表只有 3 个：calculator、weather、query_order

3. **admin 登录**
   - 退出登录
   - 用户名：`admin`，密码：`admin123`
   - 点击登录
   - 预期：左侧显示用户信息 `admin`，角色 `admin`
   - 预期：可用工具列表有 6 个：calculator、weather、grep、query_order、delete_order、send_email

### 验收要点

- ✅ 未登录请求返回 401
- ✅ 不同角色看到不同工具列表
- ✅ 登出后会话失效

## 场景 2：权限差异（ACL 拦截）

**演示目标**：验证 RBAC 权限差异和 ACL 中间件统一拦截。

### 步骤

1. **visitor 尝试删除订单**
   - 使用 visitor 登录
   - 在聊天框输入：`删除订单A-1001`
   - 预期：Agent 回复中包含"权限拒绝"（ACL 拦截，delete_order 对 visitor 不可用）
   - 预期：右侧事件面板显示 `acl_denied` 事件

2. **切换 admin 删除订单**
   - 退出，使用 admin 登录
   - 输入：`删除订单A-1001`
   - 预期：ACL 通过，但触发 HITL 审批流程（场景 3 继续）

3. **visitor 尝试 grep 搜索**
   - 切回 visitor 登录
   - 输入：`搜索日志错误`
   - 预期：ACL 拒绝（grep 是 admin only 工具）

### 验收要点

- ✅ visitor 调用危险工具被 ACL 拦截
- ✅ 拦截结果中包含 `denied_by: acl_middleware`
- ✅ admin 调用相同工具 ACL 通过
- ✅ 工具函数内部无权限判断代码

## 场景 3：HITL 审批流程

**演示目标**：验证人机协同中断→审批→恢复的完整流程。

### 步骤

1. **触发中断**
   - 使用 admin 登录
   - 输入：`删除订单A-1001`
   - 预期：Agent 回复"该操作需要审批"
   - 预期：右侧审批面板出现一张审批卡片
   - 预期：卡片显示工具名 `delete_order`、风险等级 `high`、参数 `{order_id: A-1001}`

2. **拒绝审批**
   - 点击审批卡片的"拒绝"按钮
   - 填写原因：`风险太高`
   - 预期：审批卡片状态变为"已拒绝"
   - 预期：Agent 回复"操作已被拒绝"

3. **再次触发并批准**
   - 输入：`删除订单A-1002`
   - 审批卡片出现后点击"批准"
   - 预期：审批卡片状态变为"已批准"
   - 预期：工具执行，返回"订单 A-1002 已删除"

### 验收要点

- ✅ 高风险工具触发 HITL 中断
- ✅ 审批卡片包含完整信息（工具名、参数、风险等级）
- ✅ 拒绝后工具不执行
- ✅ 批准后工具正确执行
- ✅ 中断→审批→恢复全流程闭环

## 场景 3.5：节点级中断（计划审批）

**演示目标**：验证"先生成执行计划，确认后再执行"的节点级中断和恢复流程。

### 步骤

1. **触发节点级中断**
   - 使用 admin 登录
   - 勾选聊天输入框左侧的"⚠️ 执行前确认"开关（对应 API 字段 `confirmBeforeExecute`）
   - 输入：`查询北京天气`，发送
   - 预期：Agent 生成执行计划（如调用 weather 工具），在执行前中断
   - 预期：右侧审批面板出现审批卡片，类型为 `node`（节点级），节点名 `plan_review`
   - 预期：卡片显示 Agent 的执行计划摘要

2. **批准执行计划**
   - 点击审批卡片的"批准"按钮
   - 预期：审批卡片状态变为"已批准"
   - 预期：Agent 继续执行计划中的工具调用（weather 工具被调用）
   - 预期：返回天气查询结果

3. **拒绝后重新规划**
   - 保持"⚠️ 执行前确认"开关开启
   - 输入：`删除订单A-1001`，发送
   - 预期：Agent 生成删除订单的执行计划，触发节点级中断
   - 点击"拒绝"，填写原因：`该订单不能删除`
   - 预期：Agent 收到拒绝反馈，重新规划（如建议其他操作）

### 验收要点

- ✅ 勾选"执行前确认"开关（API 字段 `confirmBeforeExecute`）触发节点级中断，消息文本不再参与触发判断
- ✅ 中断发生在 LLM 决定工具调用后、执行前
- ✅ 审批卡片显示执行计划摘要
- ✅ 批准后工具按计划执行
- ✅ 拒绝后 LLM 收到反馈并重新规划

## 场景 4：Supervisor 多 Agent 路由

**演示目标**：验证 supervisor 将请求路由到不同子 Agent。

### 步骤

1. **数学问题 → math_agent**
   - 输入：`计算 23 乘以 19`
   - 预期：右侧事件面板显示 `supervisor_route` → `math_agent`
   - 预期：工具调用 `calculator`，返回 `23 * 19 = 437`

2. **天气查询 → search_agent**
   - 输入：`北京天气怎么样`
   - 预期：右侧事件面板显示 `supervisor_route` → `search_agent`
   - 预期：工具调用 `weather`，返回北京实时天气数据

3. **订单查询 → general_agent**
   - 输入：`查询我的订单`
   - 预期：右侧事件面板显示 `supervisor_route` → `general_agent`
   - 预期：工具调用 `query_order`，返回当前用户的订单列表

### 验收要点

- ✅ 不同类型问题路由到不同子 Agent
- ✅ 子 Agent 只能访问自己的工具（math_agent 没有 weather）
- ✅ supervisor 正确汇总子 Agent 结果

## 场景 5：上下文裁剪与摘要压缩

**演示目标**：验证长对话自动裁剪和 LLM 摘要压缩。

### 步骤

1. **快速发送多轮消息**
   - 点击前端"长对话裁剪"演示按钮
   - 或手动连续发送 10+ 条消息：
     - `计算 1+1`
     - `上海天气`
     - `计算 100/4`
     - `查询订单`
     - `北京天气`
     - `计算 50*3`
     - `广州天气`
     - `计算 99-33`
     - `深圳天气`
     - `我的订单`
   - 预期：每条消息都有正常回复

2. **观察摘要压缩事件**
   - 查看右侧事件面板
   - 预期：出现 `summary_compress` 事件
   - 预期：事件详情显示压缩前后的消息数（如 `12 -> 8`）

3. **验证后续对话正常**
   - 继续发送消息：`计算 7*8`
   - 预期：Agent 仍能正常回复（摘要后上下文完整）

### 验收要点

- ✅ 超过 token 阈值触发摘要压缩
- ✅ system 消息始终保留
- ✅ tool_call 和 tool_result 配对不被拆散
- ✅ 摘要后 Agent 仍能正常对话

## 场景 6：长期记忆与跨会话偏好

**演示目标**：验证长期记忆的提取、存储和跨会话读取。

### 步骤

1. **会话 A：用户表达偏好**
   - 使用 admin 登录
   - 选择线程 `t_demo_1`
   - 输入：`我喜欢用Python`
   - 预期：Agent 回复确认偏好

2. **验证记忆已保存**
   - 点击前端"记忆"标签
   - 预期：显示 `preferred_language: Python`

3. **会话 B：跨会话读取偏好**
   - 切换到线程 `t_demo_2`
   - 输入：`帮我写一个脚本`
   - 预期：Agent 回复中提及用户偏好 Python（从长期记忆中读取）

4. **验证用户隔离**
   - 退出 admin，使用 visitor 登录
   - 点击"记忆"标签
   - 预期：visitor 没有偏好记录（与 admin 隔离）

5. **手动写入记忆**
   - 在记忆面板手动添加 `answer_style: detailed`
   - 发送消息验证效果
   - 预期：后续回复更详细

### 验收要点

- ✅ 用户偏好从对话中自动提取
- ✅ 偏好写入长期记忆（MemoryStore）
- ✅ 不同线程间共享长期记忆
- ✅ 不同用户的记忆完全隔离
- ✅ 手动写入记忆后影响后续对话

## 场景 6.5：记忆冲突消解与整合（记忆系统 v2）

**演示目标**：验证偏好变更的修订历史、记忆检索强化，以及整合（遗忘/画像/沉淀）流程。

### 步骤

1. **偏好变更与修订历史**
   - 输入：`我喜欢用Python`，等待提取完成
   - 再输入：`以后请都用Go`（同线程或另一线程均可）
   - 预期：记忆面板中 `preferred_language` 变为 `Go`，条目上出现"⏳1"修订标记（悬停可见旧值 Python）

2. **记忆面板结构化展示**
   - 预期：条目按类型分组（偏好/身份/事实/情景），带重要度星标
   - 预期：悬停条目显示来源线程与原话摘录

3. **整合记忆**
   - 点击"🧹 整合记忆"按钮
   - 预期：提示整合结果（归档条数、画像更新、沉淀的新事实）
   - 预期：出现 `user_profile` 用户画像条目；情景碎片被归档进"已归档"折叠区（真实 LLM 下还会沉淀出新事实）

### 验收要点

- ✅ 偏好变更不再被"已存在"挡住：新值生效且旧值进入修订历史
- ✅ 记忆条目结构化（类型/重要度/来源可追溯）
- ✅ 整合后生成用户画像，低价值情景被归档遗忘
- ✅ 整合在 mock 模式下走规则降级，接入真实 LLM 后效果更完整

## 演示顺序建议

```
场景 1（登录）→ 场景 2（ACL）→ 场景 3（HITL工具级）→ 场景 3.5（HITL节点级）
→ 场景 4（多Agent）→ 场景 6（记忆）→ 场景 5（上下文裁剪）
```

- 场景 5 放最后，因为需要积累多轮消息才能触发裁剪
- 场景 6 紧跟场景 4，流程自然

## 快速演示（5 分钟版）

仅演示最核心的 3 个场景：

1. **登录 + ACL**（1 分钟）：visitor 登录 → 尝试删除订单 → ACL 拒绝 → admin 登录 → 删除订单 → 触发审批
2. **HITL 审批**（2 分钟）：批准删除 → 工具执行 → 再次触发 → 拒绝 → 工具不执行 → 节点级中断：`查询天气，确认后再执行`
3. **多 Agent + 记忆**（2 分钟）：数学计算 → 天气查询 → 表达偏好 → 换线程验证偏好

## 前端演示按钮

前端页面内置 5 个一键演示按钮（点击后自动执行，每步在聊天区以 🎬 系统消息提示）：

| 按钮 | 对应场景 | 自动操作 |
|------|----------|----------|
| Visitor越权 | 场景 2 | 校验 visitor 登录 → 删除订单A-1001 → ACL 拒绝 |
| Admin审批 | 场景 3 | 校验 admin 登录 → 删除订单A-1001 → 弹出审批卡片 → 批准/拒绝 |
| 工具路由 | 场景 4 | 依次调用「计算 / 天气 / 订单」展示 Supervisor 路由到不同子 Agent |
| 长对话裁剪 | 场景 5 | 连续发送 10 条混合消息（含订单查询大输出）→ 触发上下文裁剪 → 检测 `summary_compress` 事件并提示 |
| 记忆管理 | 场景 6 | 表达偏好 → 询问偏好验证保存 → 刷新记忆面板 → 提示跨会话验证 |

> **长对话裁剪提示**：默认阈值较高（`MAX_TOKENS=8000`，触发比例 0.8 = 6400 tokens），10 轮可能不够触发。快速演示可在启动时调低阈值：
> ```bash
> MAX_TOKENS=1500 SUMMARIZE_THRESHOLD_RATIO=0.5 SUMMARY_TARGET_TOKENS=200 ./agent-server.exe
> ```
> 此时约 3 轮订单查询即可触发裁剪，事件面板显示 `📦 Context compressed: N -> M messages`。
